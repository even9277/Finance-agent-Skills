## 6. 统一目标（本轮治理）

在不大改业务逻辑前提下，优先达成三件事：

1. **看得清**：每轮对话能回答“每一步发生了什么、为什么这么走、哪里失败/降级”。
2. **量得出**：关键环节有可重复评测结果（route/rewrite/entity/field）。
3. **可迭代**：线上问题可沉淀为评测样本，形成“改动-验证-复盘”闭环。

## 9. 风险与应对

1. 风险：报告写太重导致性能负担。  
   - 应对：先输出轻量摘要版，详细版异步生成。

2. 风险：字段改动导致历史 trace 不兼容。  
   - 应对：加 `schema_version`，老版本兼容读取。

3. 风险：观测太多反而看不懂。  
   - 应对：先固定“8段报告模板”，不做无限扩展。

4. 风险：评测样本与真实问题脱节。  
   - 应对：每周回收线上 bad case，更新样本集。
