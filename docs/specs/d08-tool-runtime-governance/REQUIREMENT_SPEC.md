# D08 对话工具运行时治理需求

## 目标

受控对话在执行已经校验的只读工具计划时，除请求级总并发、超时和有限重试外，还必须实施 API family 并发、最小调用间隔、带退避的瞬时错误重试、工具级三态熔断和可选 Redis 跨实例共享状态。

## 已确认范围

- 仅接入受控对话模式；报告 Agent 工具隔离 D07 不在本轮。
- D09 实体解析另立任务；D10 暂停。
- 不修改 `D:/FinanceProject/Finance/金融Agent项目描述文档/` 下任何材料。
- 默认测试不得调用外部服务；受保护 Live E2E 必须从真实聊天入口调用真实模型和只读金融 API。
- 不增加长期双轨、兼容 Adapter、新数据库表或生产依赖。

## 可观察行为

1. 全局并发仍受 `RunBudget.max_concurrency` 约束；同一 API family 额外受独立并发和最小间隔约束。
2. timeout、429 和短暂 5xx 才能有限重试；重试使用有界退避和 jitter，并在可用时尊重 Retry-After。
3. 每个工具维护 Closed、Open、HalfOpen 状态；Open 快速失败，恢复窗口后只放有限探测。
4. Redis 启用时多个实例共享熔断状态；Redis 不可用时退回保守进程内治理，不得绕过限制。
5. 执行时重新检查健康状态；计划阶段快照不构成执行授权。
6. 失败使用稳定 `RATE_LIMITED`、`CIRCUIT_OPEN` 等错误码，不公开 Provider 原始响应。
7. Trace/日志只记录低敏字段：`trace_id`、工具名、API family、等待耗时、尝试次数、熔断状态和稳定错误码。

## 验收

- 假时钟单元测试证明 family 并发、最小间隔、退避和完整熔断状态机。
- 集成测试证明两个运行时实例通过 Redis 观察同一熔断状态，并证明 Redis 故障本地降级。
- 现有受控对话、Skills、Web News 和 E2E 回归通过。
- 受保护 Live E2E 通过真实 HTTP Chat 入口完成至少一轮真实模型与只读数据调用，并保存脱敏证据。

## 风险与回滚

- 过严限流会增加延迟；通过可配置预算和 Trace 校准。
- Redis 脚本或时钟错误可能错误熔断；Redis 不是业务真源，本地状态仍可工作。
- 回滚为撤销本分支单一提交；不涉及数据迁移。
