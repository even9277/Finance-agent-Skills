# 八股面试问题总结

把「八股文」片段转成**可背诵、可口述、能学以致用**的面试问答文档；面向**完全零基础**，用**一线开发常见情景**把枯燥原理讲活。支持 **MySQL / Redis / 消息队列 / 向量库 / 网络 / 操作系统** 等后端常见八股，**按技术栈选贯穿案例**。

## 何时启用

- 用户给出一段八股文/笔记，要求提炼面试题并写回答。
- 用户要求「继续」「同上」「按之前要求」填充某 `面试问题.md` 或同类文件。
- 用户明确要：场景补全、小白向解释、贯穿案例、代码示例、**开篇一句话速记**、**口述提示**。

## 一、阅读文档（流程）

1. **读用户提供的素材**  
   八股文段落、截图说明、或附件路径；标出知识点边界与**所属技术栈**（MySQL、Redis、MQ、向量库等）。

2. **读约束文件（若存在）**  
   如目录下的 `要求.md`：编号方式、案例名、语言、是否关闭口述提示等。

3. **读已有产出尾部**  
   若**追加**到已有文件：读用户指定产出文件的**最后 80～120 行**，确认**最后一个 `###` 编号**，新内容从 **N+1** 连续编号，不重置。

4. **确认输出路径（重要）**  
   **不在 skill 里写死路径。** 用户应在**首次调用本 skill 或本会话第一次产出**时指明写入哪个 Markdown（例如 `interview-doc/redis/面试问题.md`）。若用户未说明且会话中从未约定过，**先简短询问**再写入；若用户说「写到当前打开文件」，则以**当前聚焦/附带的文件路径**为准。

## 二、分析与提炼（策略）

**提炼题目**

- 按段落主题拆成 **1～N 个** 三级标题下的主题（N 不限；用户说「子问题不限」时可多拆）。
- 每个 `###` 对应一个**可单独被问到的面试主题**；其下可用 **加粗子问**（如 **3.1** **3.2**）拆细。

**按技术栈选贯穿案例（默认参考，可被用户覆盖）**

| 技术栈 | 建议贯穿对象（示例） | 代码/命令侧重 |
|--------|----------------------|----------------|
| **MySQL / 关系型** | 同一张业务表：`user` / `user_account`（转账、慢查询、索引） | SQL + Python（如 PyMySQL） |
| **Redis** | 同一 key 设计：`user:session:{id}`、`cache:profile:{id}`（过期、穿透、雪崩） | `redis-cli` / Python redis |
| **消息队列** | 同一业务事件：`order.paid`（顺序、重复消费、死信） | 伪代码或客户端 API（Kafka/RocketMQ/Rabbit 按题意） |
| **向量数据库 / 检索** | 同一批文档块 + 一次查询（embedding、HNSW/IVF、混合检索） | Python + HTTP/SDK 短例 |
| **网络** | 同一次请求链路：浏览器 → 网关 → 服务（TCP、HTTP、DNS、TLS 分层） | `curl` / 抓包概念描述 |
| **操作系统** | 同一进程/线程故事（调度、锁、页表、IO 多路复用） | C/伪代码或 shell 概念 |

- 同一文档、连续多题尽量**共用同一贯穿对象**，降低切换成本。
- 用户指定了表名、业务名或 key 规范时，**以用户为准**。

**叙事链路（每题回答建议按此组织，可灵活合并段落，但逻辑顺序勿颠倒）**

1. **实战场景** — 一线/常见业务里**什么时候会碰到**；避免纯抽象开场。
2. **问题定义** — 把场景落成**具体问题**：现象是什么、不解决会怎样。
3. **八股理解** — 用八股里的术语讲**机制与原理**；先通俗再术语，**缺背景必补**：生活化类比或极简小例子。
4. **代码示例** — 需要时给短片段，与上文**同一贯穿对象**；语言随技术栈（SQL / Python / redis-cli / MQ 伪代码等）。
5. **开发心得 / 要点** — 选型、避坑、排查顺序。可写「大厂/一线常见做法」作**泛指**，**不虚构具体公司名**。

**补全场景、讲清取舍、专业名词括注、八股段内 step 1/2/3** — 同前，略。

## 三、输出要求（硬性）

| 项 | 规则 |
|----|------|
| 章节标题 | 仅用 **`### 编号. 题目`** |
| 全文编号 | **1、2、3…** 连续递增，不按大章重置（除非用户另有约定） |
| **开篇一句话** | 紧跟 `**回答：**` 后第一条必须是 **`**要点一句话：**`**（或 `**速记：**`），最简概括本题核心 |
| **口述提示** | **默认每题答末**增加 **`**口述提示：**`**，用**一句**话说明面试时先答什么、再展开什么（可与要点一句话呼应，勿重复粘贴全文） |
| 回答内标题 | **禁止** `####` 及以下；仅用 **`**加粗**`** 作小标题 |
| 子问题 | 允许一个 `###` 下多个 **加粗** 子问；整题至少一句 **要点一句话**；口述提示**按整题一条**即可（子问极长时可各带一句口述提示） |
| 语言 | 默认 **简体中文** |
| 风格 | **少抽象、多具象**；穿插常见线上/业务情景 |

**可选**

- 配图说明用文字描述流程，不依赖外链图。
- 若用户或 `要求.md` 写明 **关闭口述提示**，则本任务不写 **口述提示** 块。

## 四、执行清单（每次任务）

```
- [ ] 确认产出文件路径（用户首次指明或询问）；读约束与尾部编号
- [ ] 识别技术栈 → 选定/沿用贯穿案例（上表或用户指定）
- [ ] 每题：**要点一句话** → 场景→问题→八股(step)→代码→心得 → **口述提示**
- [ ] 名词括注；无 ####；编号连续
- [ ] 若用户要求关闭口述提示，则跳过口述块
```

## 五、默认约定与用户覆盖

| 项 | 默认 |
|----|------|
| 产出路径 | **用户首次在对话中指定**；未指定则询问 |
| 编号 | 全文连续 1、2、3… |
| 贯穿案例 | **按当前八股所属技术栈**用上表；MySQL 无特殊说明时可用 `user` / `user_account` |
| 关系型代码 | PyMySQL（可被用户覆盖） |
| **口述提示** | **默认开启**；`要求.md` 或用户明确说「不要口述提示」时关闭 |

## 六、全局使用（所有仓库可用）

将本目录 **`interview-bagu-qa-summary` 整个文件夹**复制到 **`~/.cursor/skills/`**（个人技能目录）。**不要**放进 `~/.cursor/skills-cursor/`（Cursor 内置，会被系统管理）。
