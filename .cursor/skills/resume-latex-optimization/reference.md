# 简历 LaTeX 优化 — 参考

## 与 `interview-project-qa-summary` 的分工

| Skill | 侧重 |
|-------|------|
| **interview-project-qa-summary** | 面试 Markdown：路径+行号、Step 展开、大厂对照、同文档前后一致 |
| **resume-latex-optimization** | 简历 `.tex`：极短 bullet、三角对齐、可信度与 LaTeX 规范 |

两者共用原则：**代码/文档事实优先**，**不替用户编造指标**。

## 本仓库用户默认约定（简历 Skill）

| 维度 | 约定 |
|------|------|
| **经历边界** | 同段实习 `\item` **可混** 多来源；以 **代码 + 用户当轮要求** 为准，**前后能讲圆、真实可信** 即可 |
| **数字** | **不写** 过假、过夸张、超出实习生可观测/职责的指标；无据则定性或无数字 |
| **动词** | 默认 **实现/优化/落地/参与**；**避免** 设计/主导/架构作动词（除非用户明确要求且可举证） |
| **目标文件** | **每轮用户指明** `.tex` 路径；英文版同步由用户当轮说明 |

## LaTeX `\item` 微格式

- 小标题：`\textbf{短期记忆与意图理解：}`（注意全角标点与英文标点的统一，按用户文件习惯）
- 中文逗号、句号与 `\textbf{}` 嵌套时避免多余空格
- 百分号：`91\%` 而非 `91%`
- 英文技术名中的下划线：`user\_id`、`to\_thread`、`t\_context\_collection`

## 效果句模板（择一，需有依据）

```latex
针对{阻塞/指代/召回/解析…}问题，通过\textbf{方案关键词}解决，{响应时间降至500ms / 准确率提升至91\%}。
```

无硬数据时：

```latex
显著降低记忆保存路径延迟并提升多轮对话可用性。
```

## 发布前自检清单

- [ ] 每条 bullet 能否用 **30 秒** 向面试官说清 **输入-输出**？混写时能否 **一句话交代来源**（不虚构组织关系）？
- [ ] 数字是否 **不过分夸张** 且在 **文档/代码/用户消息** 中有依据？
- [ ] 是否已把 **设计/主导** 降为 **实现/优化**（除非用户特批）？
- [ ] 「多租户」等强词是否已 **降级为可举证表述**（如用户级过滤）？
- [ ] 同一段实习下 bullet **总工作量** 是否仍像 **实习生贡献**？
- [ ] `_` 已转义，`\textbf` 配对正确，编译无报错

## 本对话衍生的典型提醒

1. **短期记忆异步**：优先用 **SQLAlchemy AsyncSession / asyncio.to_thread** 等 **与真实代码一致** 的表述；勿把 **另一项目** 的 `ThreadPoolExecutor + Milvus` 默认套到本 bullet。
2. **长期记忆**：**Milvus + user 过滤** 可写 **用户级隔离**；避免默认写 **「命名空间」** 除非确为 partition/collection 级隔离。
3. **两库分离**（会话库 vs 向量库）：可在一句话中定性为 **分层存储**，不必道歉；**禁止** 虚构「统一库」若实际未做。
