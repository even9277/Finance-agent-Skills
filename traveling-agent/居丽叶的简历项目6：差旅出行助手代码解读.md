**意图识别Agent（intention_agent.py）**

**职责**：根据当前用户输入 + 系统记忆 + 对话历史，输出**结构化调度计划**，不直接执行具体业务。

**核心逻辑**：

从消息列表拆出「系统记忆」和「对话历史」，拼成 prompt 的上下文。

调用 SkillLoader 动态加载所有 Skill 的 metadata，注入 Prompt，实现 **渐进式披露**

输出 JSON 中必须包含 **agent_schedule列表**，每项为 agent_name、priority、reason、expected_output 等。还包含推理过程、意图类型、关键实体、改写后的query等，供下游使用。

**调度Agent（orchestration_agent.py）**

**职责**：按意图结果调度子智能体，同优先级并行，不同优先级顺序执行，并聚合结果、回写记忆。

**核心逻辑**：

读取 IntentionAgent 的调度决策的 **agent_schedule，**按 **priority** 排序，同一 priority 的 task 一组。

_prepare_context()：读取推理过程、意图类型、关键实体、改写后的query，从 记忆模块memory_manager 取 最近的对话、用户偏好，组成上下文。

对每一组 task 调用 _execute_parallel_agents()：对每个 task 调用 _execute_agent()，同组内用 asyncio.gather 并行。

_execute_agent：从 agent_registry[agent_name] 取智能体（这里 registry 是 LazyAgentRegistry 懒加载得到的）。

_aggregate_results()：把各 agent 的 result 聚合。

_update_memory()：根据结果更新长期记忆（例如 preference 的写入、行程历史的写入等）。

**子智能体注册（lazy_agent_registry.py）**

**作用**：实现了**插件化架构**。扫描 .claude/skills 目录，动态发现并加载子智能体。

**核心机制**：

_discover_skills()：遍历 .claude/skills/，建立 skill_name 到 script_path 的映射。

__getitem__(agent_name)：

首次访问时，使用 importlib.util 动态加载对应的 agent.py 模块。

反射查找模块中继承自 AgentBase 的类。

实例化 Agent，并自动注入 memory_manager（如果构造函数需要）。

存入 cache，下次直接返回实例。

**记忆管理（context目录）**

**职责**：统一封装「短期记忆」和「长期记忆」

**短期记忆**：ShortTermMemory()，存储当前会话中的最近 N 轮对话。

**长期记忆**：LongTermMemory()，持久化到 data/memory/{user_id}.json，存偏好、行程历史、全量聊天记录等；可以跨会话。

add_message()：将对话内容写入短期和长期记忆。

get_context_for_agent()：拼成给 Agent 的上下文（长期记忆摘要 + 用户偏好 + 短期对话记忆）。

get_long_term_summary_async()：用 LLM 对长期聊天做摘要，供意图识别时使用。

**回答生成指南（Progressive Disclosure）**  
面向 LLM 的「回答要求」：严格基于知识库、不得编造、信息不足时明确说「知识库中没有相关信息」等。这部分会在 **agent.py** 里通过 SkillLoader 动态读取并注入到 prompt，实现「说明在 MD、逻辑在代码」的 Progressive Disclosure。

.claude/skills/ask-question/script/agent.py该文件自包含 RAG 问答逻辑。

**类与职责**  

**RAGKnowledgeAgent(AgentBase)**：基于向量库（Milvus Lite）做检索，再结合 LLM 生成答案。  

技术栈：Milvus Lite、sentence-transformers 做向量化、项目配置的 LLM 生成答案。

**初始化 init**  

参数：name、model、knowledge_base_path（默认 skill 下的 data/rag_knowledge）、collection_name、embedding_model、top_k。  

从 **config.RAG_CONFIG** 读取 embedding_model（支持本地路径，避免连 HuggingFace）；若路径存在则本地加载，否则回退到如 BAAI/bge-small-zh-v1.5。  

使用 **MilvusClient** 连接 knowledge_base_path/milvus_lite.db；若 collection 不存在则 **create_collection**（dimension、COSINE、auto_id=False）。  

创建 **SkillLoader**，供后续从同 skill 的 SKILL.md 拉取「回答生成指南」。  

依赖未安装或初始化失败时置 self.initialized = False，后续 reply 直接返回错误信息。

**检索 search_knowledge(query, top_k)**  

用 embedding_model.encode(query) 得到向量，在 Milvus 中 **search**，取 output_fields=["id", "content", "metadata"]。  

返回列表，每项含 id、content、metadata、distance；异常时返回空列表。

**主流程 async reply(x)**  

**解析入参**：若 x.content 是 JSON 字符串（以 { 开头），则解析并从 context.rewritten_query 或顶层 rewritten_query 取出用户 query；否则整段 content 当作 user_query。

**检索**：retrieved_docs = self.search_knowledge(user_query)。若无结果，直接返回 status: "no_knowledge"、answer 为「知识库中没有找到相关信息」的 JSON Msg。

**拼 prompt**：将检索到的片段拼成「知识库信息」；通过 **skill_loader.get_skill_content("ask-question")** 读取 SKILL.md 中的「回答生成指南」作为任务说明（Progressive Disclosure）；再加上「严格基于知识库、不得编造」等约束。

**调用 LLM**：response = await self.model(messages)；兼容异步生成器或普通 content/text 属性，得到字符串 answer；若 LLM 误输出 JSON 外形则尝试从 answer/content 字段提取。

**统一返回**：返回 Msg，content 为 JSON 字符串：{status, query, answer, retrieved_documents}；retrieved_documents 为摘要版（如 content 截断到 200 字）便于编排器展示。

编排器调用本 skill 时，只需传入统一格式的 Msg（含 context.rewritten_query），即可得到上述 JSON 结构的 Msg.content，无需关心 SKILL.md 与 agent 内部实现细节；SKILL.md 负责「何时用、返回啥、如何初始化」，agent.py 负责「怎么检索、怎么调 LLM、怎么拼 prompt」。

**连接与可用性（circuit_breaker.py & llm_resilience.py）**

CircuitBreaker：维护状态 closed / open / half_open；连续失败达阈值则打开，一段时间后半开试探，成功次数达标后关闭；

retry_with_backoff()：对传入的协程工厂做有限次重试，采用指数退避算法。

run_health_check()：用最小请求探测 LLM 是否可达。



**全文评论**
