# Fund Compare

## Purpose

对两只或多只基金、ETF、LOF、联接基金或 QDII 做可核对横向比较。先确认候选是否可比，再用基础、净值、行情和份额证据解释差异，最后给出适配性结论。

## When to Use

- 用户明确要“对比/比较/PK/选一个”两只或多只基金、ETF、LOF、联接基金。
- 用户希望基于可核对的数据比较近期表现、净值、份额规模、产品类型或跟踪特征。
- 用户希望结合自身风险偏好、投资周期、回答偏好，得到更适合自己的排序或结论。

## When Not to Use

- 只有一个基金、筛选一类 ETF 或解释单一产品异动时不使用本 Skill。
- 跨品类且用户未确认比较口径时，不直接输出强排序。

## Required Inputs

- 用户原始问题。
- 最少两个待比较基金实体；若实体不清晰，需要先说明无法稳定比较。
- 用户画像摘要：仅用于调整输出结构和结论表达，不可代替证据。

## Workflow

1. 先识别候选基金名称，目标是得到 2 到 4 个比较对象。
2. 每个对象先查基础信息，再补净值、份额或场内行情，避免只看单一指标下结论。
3. 如果同名或近似基金过多，优先选择更匹配用户问题的候选；仍不清楚时要显式说明歧义。
4. 比较时优先讲清楚“可比口径”，不要把场内 ETF、场外联接基金、QDII、黄金主题基金混为一类。
5. 结论必须引用已获取证据；证据不足时只给出保守建议或明确降级。

## Tool Use Guide

- 基础信息工具对每个候选都执行；ETF 候选可补 `get_etf_basic_info`。
- 净值、场内行情和份额分别支持表现、交易与规模维度，不能互相冒充。
- 异动新闻归因转 `market-move-explain`，本 Skill 不使用网页搜索。

## Evidence Rules

- 至少两个不同主体；每个主体都要有基础信息，并至少命中净值、行情或份额之一。
- 同类基金可以排序；跨类基金只比较配置属性和适配人群。
- 某候选缺数据时单独标记证据不足，不能用另一候选的数据推断。

## Degrade Policy

- 找不到至少两个可比对象：说明缺少明确基金名称，提示用户补充。
- 基础信息拿到了，但表现类数据不足：只说明产品差异与已知风险，不做强排序。
- 工具结果为空或冲突：保留已确认事实，拒绝编造比较结论。

## Output Contract

- 默认结构：
  - 先给结论，再给对比维度、主要风险、适配建议、数据来源。
- `response_pref=risk_first`：
  - 先给风险和不确定性，再给结论和推荐顺序。
- `response_pref=concise`：
  - 保留结论、2 到 3 个核心对比点、1 段风险提示。
- 始终显式标注：数据来源为 Tushare，并尽量给出数据日期或财报期。
